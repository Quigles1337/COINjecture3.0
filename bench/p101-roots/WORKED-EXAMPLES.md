## Example 1: tx_root of three transactions

The list is `[tx1, tx2, tx1]`, where `tx1` and `tx2` are the two worked transactions
of the normative vectors (`out.tx1.bytes`, `out.tx2.bytes` in
`bench/p007-vectors/encoding-v1.vectors.txt`). A block could not hold `tx1` twice,
because V4 would reject the second; the root is defined for any list, and the
repeat is here to show that a repeated entry is hashed as an entry of its own.

Shape for a count of 3: the split point is 2, so the top is
`node(node(leaf 0, leaf 1), leaf 2)`. The third leaf is not paired with itself.

### A proof that tx1 is at position 2 of 3

The proof is the count `3`, the position `2`, the 188 transaction bytes and one
sibling hash, lowest first:

```text
14058d693cdfa83e1c5365c0346c3e0789e4a5c050f5de7d64a0fab3714c3950
```

For position 2 of 3 the split rule puts the leaf on the right of the top node, so
the verifier computes `H(D_TXNODE ‖ sibling ‖ leaf 2)`, then `H(D_TXROOT ‖ 3 ‖ top)`,
and compares with `tx_root`.

## Example 2: the state commitment of four accounts

Three addresses are `addr` of the RFC 8032 test keys 1 to 3 (`out.addr.key1`,
`out.addr.key2`, `out.addr.key3` in the normative vectors). The fourth, called
`near`, is the address of key 1 with its last bit flipped. No key is known for it;
an address read from a transaction is any 32 bytes. It shares 255 bits with the
address of key 1, to show that a long shared prefix costs one node, not a chain.

### A proof that key1's account is present

The proof is the count `4`, the leaf (address, balance, nonce) and three steps,
lowest first, each a split index and a sibling hash:

```text
split 255  sibling 183936ce3697ca26379fe4d829be41d6034c9c02e1a721e25cfd3e9615da54c0
split   1  sibling 40bc503ca99c1e74bc766fbc4aa0273b615644a5b638abfa4170319bdf0d829f
split   0  sibling 5fcdfcc494b2fba4a6b59e5956ae36688cbcabb30798704f071943855570b8cc
```

At each step the verifier reads the bit of the address at the split index: 1 puts
the running hash on the right, 0 on the left. Bits 255, 1 and 0 of key1's address
are 1, 0 and 1. The splits must decrease strictly from the leaf upward.

### A proof that an address is absent

The address asked for is `d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a`
(the 32 bytes of test key 1's public key, used here only as an address with no
account). Following its bits down the tree reaches the leaf of **key2**.
The proof is the count `4`, that leaf, and its steps:

```text
split   1  sibling 11ad17b62796475a071ae0adbe1f46a9290b44fabdff5248ef7aee9d2c70703f
split   0  sibling 5fcdfcc494b2fba4a6b59e5956ae36688cbcabb30798704f071943855570b8cc
```

The verifier takes each side from the bits of the address it asked for, recomputes
the commitment, and checks that the leaf's address is a different one. If the
address had an account, the same walk would have ended at it.
